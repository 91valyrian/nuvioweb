## 홈페이지 리뉴얼, 무엇부터 확인해야 하나요?

**기존에 검색되던 주소를 새 사이트에서도 어떻게 연결할지 먼저 정해야 합니다.** 디자인과 메뉴를 바꾸면서 예전 페이지를 삭제하거나 주소를 바꾸면, 검색 결과나 외부 링크에서 들어온 방문자가 원하는 내용을 찾지 못할 수 있습니다.

리뉴얼은 모든 URL을 바꾸는 작업일 필요가 없습니다. 기존 페이지의 목적이 유지된다면 주소도 유지하는 방법을 우선 검토하세요. 주소를 변경해야 한다면 이전 페이지와 새 페이지의 대응 관계를 정리하고, 영구 리디렉션과 내부 링크를 함께 점검해야 합니다.

이 글은 기존 사이트를 운영 중인 담당자가 제작사와 리뉴얼 범위를 협의할 때 사용할 수 있는 점검표입니다. 새 홈페이지의 제작 범위부터 정해야 한다면 [홈페이지 리뉴얼 서비스](/service/renewal)와 [제작 비용의 구성](/columns/homepage-cost-guide)을 함께 확인해 보세요.

## 1. 조회수가 아니라 기존 페이지 목록부터 정리하세요

오픈 전에 현재 URL, 페이지 목적, 검색 노출·클릭, 문의와 연결되는 행동을 목록으로 정리하세요. Search Console의 검색 실적과 페이지 색인 보고서, 분석 도구의 방문 페이지, 기존 사이트맵을 함께 확인하면 누락을 줄일 수 있습니다.

검색 유입이 적은 페이지도 거래처가 즐겨찾기했거나 제안서에 주소가 실렸을 수 있습니다. 방문 수 하나만으로 삭제 여부를 결정하지 말고 실제 사용 목적과 외부 연결도 확인해야 합니다.

- 검색에서 클릭이 발생하는 서비스·제품 페이지
- 광고, 블로그, 제안서에 연결한 주소
- 문의와 다운로드로 이어지는 페이지
- 유지할 자료와 폐기할 자료
- 이미지·첨부파일처럼 본문 밖에서 직접 연결되는 파일

리뉴얼 전후를 비교할 수 있도록 데이터를 저장할 때는 조회 기간과 측정 기준도 함께 남기세요.

변경된 주소는 서버에서 **301 또는 308 영구 리디렉션**으로 처리할 수 있습니다. 관련 없는 페이지를 모두 홈페이지로 보내는 방식은 피하고, 중간 주소를 여러 번 거치지 않도록 최종 목적지로 바로 연결하세요.

Google은 사이트 이전 시 URL 대응표, 영구 리디렉션, 새 사이트 검증과 모니터링을 권장합니다. 자세한 기준은 [Google의 사이트 이전 안내](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)에서 확인할 수 있습니다.

## 3. 제목·canonical·사이트맵을 새 주소와 맞추세요

리디렉션만 설정하고 본문의 링크나 검색 메타 정보를 예전 주소로 남겨두면 관리가 어려워집니다. 새 주소가 정해지면 아래 항목을 함께 확인하세요.

- 각 페이지의 제목과 설명이 실제 내용을 설명하는지
- canonical이 공개할 대표 URL을 가리키는지
- 메뉴·본문·제작 사례 링크가 최종 주소로 직접 연결되는지
- 구조화 데이터의 URL·이미지·조직 정보가 맞는지
- 사이트맵에 정상 공개 페이지가 포함되는지
- RSS를 운영한다면 링크와 발행일이 유효한지

사이트맵은 검색 로봇에게 URL을 알려주는 수단이며 제출만으로 순위가 보장되지는 않습니다. 네이버 역시 콘텐츠 노출이 적을 때 RSS와 사이트맵 제출을 권장합니다. [네이버 피드 제출 안내](https://searchadvisor.naver.com/guide/request-feed)를 기준으로 실제 제출 결과도 확인하세요.

## 4. 개발용 검색 차단을 운영 사이트에 남기지 마세요

개발 환경의 `noindex`나 접근 제한이 운영 환경에 남아 있으면 검색 수집·색인에 영향을 줄 수 있습니다. 반대로 관리자 로그인이나 백업 페이지는 검색할 이유가 없는 페이지이므로 공개 콘텐츠와 구분해 관리해야 합니다.

`robots.txt`는 크롤링을 제어하고, `noindex`는 색인 제외를 요청합니다. 역할이 같지 않으므로 설정 파일이 있다는 사실보다 실제 응답과 페이지 메타를 확인하세요. HTTP와 HTTPS, www 주소도 대표 주소로 일관되게 연결되는지 점검합니다.

## 5. 오픈 검수에는 문의 접수까지 포함하세요

검색 방문자가 들어와도 연락할 수 없다면 사이트의 목적을 달성하기 어렵습니다. PC와 휴대전화에서 직접 문의를 제출하고, 성공 안내뿐 아니라 실제 저장·알림 수신까지 확인하세요.

<table>
  <thead><tr><th>점검 시점</th><th>확인할 항목</th></tr></thead>
  <tbody>
    <tr><td>오픈 전</td><td>기존 URL 목록, 이전표, 콘텐츠 백업, 새 사이트의 모바일·문의 검수</td></tr>
    <tr><td>오픈 직후</td><td>대표 URL 응답, 리디렉션, robots·noindex, canonical, 사이트맵, 문의 저장</td></tr>
    <tr><td>오픈 이후</td><td>크롤링 오류, 페이지별 색인, 검색어별 노출·클릭, 검색 유입의 문의 완료</td></tr>
  </tbody>
</table>

문의 분석에는 이름·전화번호 같은 개인정보를 이벤트로 보내지 말고, 문의 완료 여부와 폼 구분처럼 목적에 필요한 정보만 사용하세요.

## 리뉴얼 후 순위는 언제 안정되나요?

사이트 규모, 주소 변경 범위와 검색엔진의 재수집 상황에 따라 다르므로 일괄적인 회복 날짜를 약속하기는 어렵습니다. 전체 방문 수만 보기보다 기존에 유입되던 검색어와 페이지가 새 사이트에서도 연결되는지 확인하는 것이 먼저입니다.

이전에 홈페이지가 접속되지 않았던 기간이 있다면 디자인 개편의 영향과 장애의 영향을 구분해야 합니다. 복구 날짜와 배포 날짜를 기록하고, 그 전후의 같은 기준 데이터를 비교하세요. 단기간의 변화를 보고 주소를 반복해서 바꾸는 행동은 피하는 편이 좋습니다.

## 제작사와 미리 합의할 세 가지
