## 원하는 홈페이지를 만들려면 첫 요청부터 구체적이어야 합니다

**클로드 코드로 홈페이지를 제작할 때는 회사의 서비스와 방문자가 할 행동을 먼저 전달하고, 첫 화면을 확인한 뒤 수정 범위를 좁혀가는 순서가 좋습니다.** “예쁘게 만들어줘”에서 시작하기보다 어떤 정보를 읽고 어디로 이동해야 하는지 정하면 결과를 판단하기 쉬워집니다.

누비오는 홈페이지 제작사의 관점에서 원고를 전달하는 방법, 화면을 만드는 요청문, 결과를 보고 고치는 순서를 안내하겠습니다. 처음에는 서비스 소개 한 페이지로 시작해 보세요. 직접 만든 시안은 회사에 필요한 내용과 원하는 디자인을 구체화하는 자료가 될 수 있습니다. 이후 실제 문의 연결과 공개 환경까지 준비하면 운영할 홈페이지의 범위가 보입니다.

아래에서는 가상의 사무실 정리 서비스 ‘모아정리’를 예로 듭니다. 실제 납품 사례나 사용 후기가 아닌 요청 방법을 설명하기 위한 예제입니다. 제작 전 준비 자료와 전체 검수 기준은 [클로드 코드 홈페이지 제작 가이드](/columns/claude-code-homepage-guide)에서 함께 확인할 수 있습니다.

## 1. 작업할 폴더를 만들고 Claude Code를 켭니다

이 글은 **컴퓨터의 터미널에서 실행하는 Claude Code**를 기준으로 합니다. 아직 설치하지 않았다면 [Anthropic 공식 시작 안내](https://code.claude.com/docs/en/quickstart)에서 자신의 운영체제에 맞는 설치 방법과 로그인 조건부터 확인하세요. 사용 요금과 한도도 사용하는 계정 기준으로 확인합니다.

설치 후 새 터미널에서 아래 명령을 입력하면 버전이 표시되는지 확인할 수 있습니다.

```text
claude --version
```

이제 예제용 폴더를 하나 만듭니다. 아래 명령은 **일반 터미널에 한 줄씩** 입력합니다. Claude와 대화하는 창에 입력하는 요청문과 구분하세요.

```text
mkdir moa-homepage
cd moa-homepage
claude
```

`mkdir`는 폴더를 만들고, `cd`는 그 폴더로 이동하는 명령입니다. 같은 이름의 폴더가 이미 있다면 새 이름을 쓰세요. 처음 실행할 때는 안내에 따라 로그인하고 현재 작업 폴더를 확인합니다. `claude`를 찾을 수 없다는 오류가 나오면 홈페이지 제작을 요청하기 전에 공식 안내의 설치·경로 문제부터 해결해야 합니다.

여기까지 왔으면 **현재 작업 위치가 `moa-homepage`인지** 확인하세요. 다른 프로젝트를 열어둔 채 예제 작업을 시작하지 않는 것이 좋습니다. 파일 수정이나 명령 실행의 승인 화면이 나오면 대상 경로와 내용을 읽고 진행합니다.

## 2. 첫 요청에는 회사 소개와 만들 범위를 함께 적습니다

“회사 홈페이지 만들어줘”만 입력하면 회사가 무슨 일을 하는지부터 AI가 채워 넣어야 합니다. 이번에는 아래 내용을 Claude Code 대화창에 입력해 보겠습니다.

> 가상의 사무실 정리 서비스 ‘모아정리’의 소개 홈페이지를 만들려고 합니다. 소규모 회사의 총무 담당자가 서비스 범위와 진행 방법을 이해하는 페이지입니다. 아래 자료만 사용해 주세요.
>
> 서비스는 사무실 물품 분류, 수납 위치 정리, 정리 기준 안내입니다. 진행 순서는 공간과 요청사항 확인 → 작업 범위 협의 → 정리 작업 → 유지 방법 안내입니다. 첫 화면 문구는 ‘찾는 시간을 줄이는 사무실 정리’로 하고, 버튼 문구는 ‘진행 방법 보기’로 해주세요. 버튼은 같은 페이지의 진행 순서로 이동합니다.
>
> 구성은 첫 화면, 서비스 세 가지, 진행 순서, 문의 안내 순서입니다. 예제 페이지이므로 후기·고객사 로고·가격·성과 수치를 만들지 마세요. 문의 영역에는 ‘예제 페이지입니다. 실제 문의 기능은 연결하지 않았습니다’라고 표시하고, 작동하는 것처럼 보이는 제출 폼은 넣지 마세요.
>
> HTML, CSS, JavaScript로 한 페이지를 만들겠습니다. 우선 파일을 수정하지 말고, 만들 파일과 화면 구성을 짧게 정리해 주세요. 이미 파일이 있다면 먼저 확인하고 덮어쓰기 전에 알려주세요.

Claude가 제안한 구성에서 볼 것은 기술 이름의 개수가 아닙니다. **내가 준 서비스가 들어갔는지, 없는 실적이 추가되지 않았는지, 버튼이 어디로 가는지**부터 읽어보세요. 자료가 부족하면 지금 보충하면 됩니다.

이미 원고가 있다면 폴더에 `brief.md` 같은 파일로 저장해도 됩니다. “이 폴더의 brief.md를 읽고 구성해줘”라고 요청하면 같은 내용을 매번 길게 붙여넣지 않아도 됩니다. 실제 [기업 홈페이지](/service/corporate)로 확장할 계획이라면 회사·서비스별 원고와 이미지도 이때 구분해 두세요.

## 3. 첫 화면은 한 번에 확인할 수 있는 크기로 만듭니다

구성에 빠진 것이 없다면 다음 요청으로 구현을 시작합니다. 이번 예제는 설치할 개발 도구를 늘리지 않고 화면 수정에 집중하기 위해 기본 웹 파일을 사용합니다. 기존 프로젝트를 고치는 경우에는 그 프로젝트의 실행 방식과 구조를 따라야 합니다.

> 제안한 구성으로 구현해 주세요. 파일은 index.html, styles.css, script.js로 나누고, 외부 라이브러리 없이 실행되게 해주세요. 디자인은 따뜻한 흰색 배경, 진한 글자, 짙은 초록색 강조색으로 구성해 주세요. 장식보다 제목과 서비스 설명이 잘 읽히는 것이 우선입니다.
>
> 상단에는 서비스와 진행 순서로 이동하는 링크를 넣고, 모바일에서는 메뉴가 한 줄에 억지로 끼지 않도록 해주세요. 사진은 아직 없으니 임의의 고객 현장 사진이나 깨진 이미지 링크를 넣지 말고, 사진 없이도 균형이 맞는 레이아웃으로 만들어 주세요. 변경한 파일과 화면 확인 방법도 알려주세요.

완료 답변을 받으면 폴더에 파일이 생겼는지 살펴보세요. 같은 폴더의 CSS·JavaScript를 연결한 단순 페이지라면 `index.html`을 브라우저로 열어 첫 모습을 볼 수 있습니다. 다만 파일 주소로 여는 방식에는 제약이 있으므로 이후 기능 확인에는 로컬 서버를 사용하는 편이 좋습니다. 파일 주소의 제약과 서버 실행 방식은 [MDN의 로컬 테스트 서버 안내](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Tools_and_setup/set_up_a_local_testing_server)에서도 확인할 수 있습니다.

이때 바로 “전체적으로 더 예쁘게”라고 요청하기보다 첫 화면을 한 번 천천히 읽어보세요. 예제 제목인 ‘찾는 시간을 줄이는 사무실 정리’가 보이는지, 아래 서비스 세 가지가 원고와 맞는지, ‘진행 방법 보기’를 누르면 해당 영역으로 이동하는지 확인합니다. 문제가 있다면 그 위치부터 고칩니다.

## 4. 로컬 주소를 열어보고, 안 열리면 상태부터 묻습니다

Claude가 “만들었습니다”라고 답했다고 브라우저가 자동으로 열리는 것은 아닙니다. 실행 방법이 어렵거나 로컬 주소가 없다면 다음처럼 요청하세요.

> 이 페이지를 로컬 서버에서 확인하고 싶습니다. 현재 컴퓨터에서 사용할 수 있는 실행 도구부터 확인해 주세요. 가능하면 별도 패키지 설치 없이 이 폴더만 제공하고, 내 컴퓨터에서만 접근하는 주소로 실행해 주세요. 정확히 열 주소, 서버가 실행 중인지, 종료 방법을 알려주세요. 직접 실행할 수 없다면 내가 입력할 명령과 입력할 터미널을 구분해 주세요.

답변에 나온 `http://localhost:포트번호` 또는 `http://127.0.0.1:포트번호` 형태의 주소를 브라우저 주소창에 붙여넣습니다. 포트번호와 파일 경로는 실제 안내받은 값을 쓰세요. 이 주소는 내 컴퓨터에서 확인하기 위한 것이며 고객에게 전달할 공개 홈페이지 주소는 아닙니다.

‘연결할 수 없음’이 뜨면 디자인 요청을 더 보내기 전에 서버 상태를 확인합니다.

> 방금 안내한 주소를 열었는데 ‘연결할 수 없음’이 나옵니다. 서버가 계속 실행 중인지, 사용 중인 포트와 내가 연 주소가 일치하는지 확인해 주세요. 원인을 확인한 뒤 다시 열 주소를 알려주세요.

이미 다른 작업이 쓰는 포트라면 그 작업을 종료하기보다 다른 빈 포트를 사용하도록 요청하세요. 화면이 열렸지만 수정이 반영되지 않으면 새로고침하고, 지금 보고 있는 주소와 수정한 폴더가 같은지도 확인합니다. 이 단계에서는 오류 메시지를 그대로 전달하는 편이 “안 돼요”보다 문제를 좁히기 좋습니다.

## 5. 마음에 안 드는 부분은 위치와 원하는 상태를 말합니다

첫 화면을 보고 나면 바꾸고 싶은 부분이 생깁니다. 여기서부터는 **한 번에 확인할 수 있는 수정 묶음**으로 요청해 보세요. 예를 들어 제목, 버튼, 카드 간격을 고친 뒤 결과를 보고 다음으로 넘어가는 식입니다.

> PC 첫 화면에서 제목이 세 줄로 나뉘어 너무 길게 느껴집니다. 제목 영역의 폭을 조정해 두 줄 안에서 자연스럽게 읽히게 해주세요. 모바일에는 두 줄을 강제하지 말고 화면 폭에 맞게 흐르게 해주세요. 서비스 설명과 섹션 순서는 유지해 주세요.
>
> ‘진행 방법 보기’ 버튼은 첫 화면 설명 바로 아래에 배치하고 배경과 충분히 구분되게 해주세요. 서비스 카드는 본문 줄 간격을 조금 넓히고, 카드 사이 간격은 동일하게 맞춰주세요. 수정 후 무엇을 바꿨는지 알려주세요.

“세련되게”, “고급스럽게”라는 말도 방향을 설명할 때는 쓸 수 있습니다. 다만 실제로 고칠 때는 **어디가 불편하고 어떻게 보이면 좋은지**를 붙여주세요. [시안 피드백을 수정 기준으로 정리하는 방법](/columns/nuvio-design-feedback)도 같은 원리입니다.

말로 설명하기 어려우면 현재 화면을 캡처해 작업 폴더에 저장한 뒤 파일 경로와 함께 질문할 수 있습니다. Claude Code는 이미지 경로를 전달해 내용을 분석하는 방식을 지원합니다. 입력 방법은 [공식 이미지 활용 안내](https://code.claude.com/docs/en/common-workflows#work-with-images)를 참고하세요.

> 이 폴더의 feedback.png를 봐주세요. 표시한 서비스 카드 두 번째 줄이 유독 좁아 보입니다. 다른 카드와 본문 폭·안쪽 여백을 비교해 원인을 확인하고 맞춰주세요. 이미지에 표시하지 않은 다른 섹션은 유지해 주세요.

예시 파일명을 그대로 쓰기 전에 실제로 캡처를 저장해야 합니다. 캡처에는 페이지 주소와 화면 폭도 함께 남기면 좋습니다. 변경 후에는 새로고침해서 표시한 부분이 고쳐졌는지 직접 비교하세요.

이 단계에서 문구를 바꿔도 회사의 강점이 드러나지 않거나 페이지 순서를 계속 바꾸고 있다면, 화면 장식보다 정보 구성부터 정리할 시점입니다. 누비오의 [기업 홈페이지 제작](/service/corporate)에서는 회사·서비스·사례·문의의 역할을 나누고 필요한 콘텐츠와 기능을 함께 설계합니다. 지금 만든 시안도 원하는 방향을 설명하는 출발점으로 활용할 수 있습니다.

## 6. 모바일은 작은 PC 화면처럼 생각하지 말고 눌러봅니다

PC 화면이 정돈되면 브라우저 개발자 도구의 모바일 보기로 전환해 보세요. 이 예제에서는 390px 전후의 폭에서 먼저 확인하고, 조금 더 좁고 넓은 폭으로도 움직여봅니다. 이 숫자는 확인 기준이지 모든 휴대전화를 대표하는 규격은 아닙니다.

스크롤하면서 제목이 잘리지 않는지, 서비스 카드가 화면 밖으로 나가지 않는지, 상단 링크와 버튼이 손가락으로 구분하기 쉬운지 봅니다. 가로로 밀어봤을 때 의도하지 않은 빈 공간이 보이면 넘치는 요소가 있을 수 있습니다.

> 화면 폭 390px에서 첫 화면 제목의 줄바꿈과 서비스 카드 너비를 확인해 주세요. 페이지 전체에 가로 스크롤이 생기면 어떤 요소가 넘치는지 찾아 수정해 주세요. 상단 링크와 진행 방법 버튼이 목표 섹션으로 이동하는지도 점검해 주세요. 브라우저를 직접 조작할 수 없는 환경이라면 확인했다고 쓰지 말고 내가 점검할 순서를 알려주세요.

휴대전화에서 직접 확인할 때 `localhost`를 입력하면 컴퓨터가 아닌 **그 휴대전화 자신**을 가리킵니다. 이 예제의 로컬 전용 서버 주소로는 다른 기기에서 접속할 수 없습니다. 기기 검수용 접속 방법이나 미리보기 환경은 별도로 준비해야 합니다. 브라우저의 모바일 보기는 유용한 첫 점검이고, 공개 전 실제 기기 확인도 필요합니다.

## 7. 수정이 끝나면 다음 작업자가 볼 메모를 남깁니다

페이지가 마음에 들면 지금 상태를 한 번 저장해 두세요. Git을 사용한다면 변경 내용을 검토하고 커밋할 수 있습니다. 익숙하지 않다면 우선 현재 폴더를 별도 이름으로 복사해 두는 방법도 있습니다. 다음 수정 후 문제가 생겼을 때 비교할 기준을 남기는 것이 목적입니다.

반복해서 지켜야 할 규칙은 프로젝트의 `CLAUDE.md`에 정리할 수 있습니다. [공식 프로젝트 지침 안내](https://code.claude.com/docs/en/memory)를 참고해 이 예제에는 아래처럼 짧게 남겨보세요. 지침 파일이 있다고 결과 확인을 생략하는 것은 아닙니다.

> 현재 프로젝트에 CLAUDE.md가 있는지 먼저 확인해 주세요. 없다면 새로 만들고, 있다면 기존 규칙을 보존하며 다음 내용을 반영해 주세요. 이 사이트는 모아정리 예제 페이지이고, HTML·CSS·JavaScript를 사용합니다. 확인되지 않은 후기와 실적은 넣지 않습니다. 문의 기능은 아직 연결하지 않았습니다. 이번에 사용한 로컬 서버 실행·종료 방법과 파일별 역할을 기록해 주세요.

마지막으로 완료 보고를 한 번 더 요청합니다.

> 지금까지 바뀐 파일, 내가 수정할 원고의 위치, 실제 확인한 항목, 아직 확인하지 못한 항목을 정리해 주세요. 문의 연결과 공개 배포가 남아 있다는 점도 표시해 주세요. 코드를 읽어서 점검한 것과 브라우저에서 직접 확인한 것을 구분해 주세요.

이 메모가 있으면 다음 날 다시 시작하거나 다른 사람에게 검토를 부탁할 때도 현재 상태를 설명하기 쉽습니다.

## 직접 만든 시안을 실제 회사 홈페이지로 완성하려면

이제 화면이 열리고 원하는 문구와 배치가 보인다면 다음은 **방문자가 서비스를 이해하고 실제로 문의할 수 있는 홈페이지로 완성하는 단계**입니다. 예제 원고를 회사의 검증된 자료로 교체하고, 문의가 도착할 곳과 공개 후 수정할 방법을 정하세요.

접수 폼을 추가한다면 [문의폼 제작과 접수 오류 점검표](/columns/website-inquiry-form-checklist)를 참고하세요. 완료 문구만 보이는지, 문의가 실제로 보관·전달되는지까지 확인해야 합니다. 문의 전송은 테스트 환경과 별도 수신처에서 확인합니다.
