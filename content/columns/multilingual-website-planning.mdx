## 다국어 홈페이지는 번역할 문장보다 ‘방문자가 이동할 경로’를 먼저 정해야 합니다

**누가 어떤 언어로 정보를 찾는지, 그 언어의 페이지를 어떤 주소로 제공할지, 읽은 뒤 누구에게 문의할지**부터 정하세요. 한국어 문장을 전부 번역하고 언어 전환 버튼만 붙이는 방식으로는 실제 운영 범위가 정리되지 않습니다.

예를 들어 해외 거래처가 제품 사양을 확인하는 사이트와 해외 소비자가 직접 구매하는 사이트는 필요한 정보가 다릅니다. 전자는 제품 자료와 담당자 연결이 우선일 수 있고, 후자는 판매 지역·배송·결제 등 별도의 검토가 필요합니다. 이 글은 회사·제품 소개와 상담이 중심인 기업 홈페이지를 기준으로 설명합니다.

이미 한국어 사이트가 있다면 모든 메뉴를 한꺼번에 복제하기보다, 해외 고객이 방문할 핵심 페이지와 운영 담당자를 먼저 확정하는 편이 현실적입니다. 아래 순서로 범위를 정리하면 제작 견적과 오픈 검수에서도 같은 기준을 사용할 수 있습니다.

## 1. ‘영어 지원’과 ‘특정 국가 대상 운영’을 구분하세요

영어 페이지가 있다고 해서 모든 국가에 같은 서비스를 제공할 수 있는 것은 아닙니다. 미국과 영국처럼 같은 언어를 사용하는 고객이라도 취급 제품, 문의 창구, 안내해야 할 조건이 다를 수 있습니다.

기획 단계에서는 다음 세 질문에 답해 보세요.

- **독자:** 해외 바이어, 현지 대리점, 채용 지원자 중 누구에게 보여줄 사이트인가요?
- **목표:** 제품 자료 열람, 상담 요청, 대리점 연결 중 어떤 행동으로 이어져야 하나요?
- **대응:** 들어온 문의를 어떤 언어로 누가 확인하고 답변할 수 있나요?

예를 들어 해외 바이어를 위한 영문 사이트라면 회사 소개보다 제품군·사양서·공급 상담 경로가 먼저 필요할 수 있습니다. 반대로 채용을 위한 페이지라면 업무 환경과 지원 방법이 더 중요합니다. 같은 ‘영문 홈페이지’ 견적이라도 이 차이를 먼저 알려야 합니다.

이는 기획 예시이며 누비오의 특정 고객 성과를 의미하지 않습니다. 방문 목적에 따라 메뉴를 나누는 방법은 [홈페이지 정보 구조 설계 글](/columns/website-structure-seo-2026)에서도 확인할 수 있습니다.

## 2. 언어마다 다시 열 수 있는 URL을 만드세요

## 4. 언어 연결과 대표 주소 설정은 서로 다른 역할입니다

제작사와 검수할 때는 `hreflang`과 `canonical`을 구분해 물어보세요. 용어를 직접 구현할 필요는 없지만, 어떤 페이지가 서로 연결되는지는 확인할 수 있어야 합니다.

### hreflang: 같은 콘텐츠의 언어·지역 버전을 연결합니다

Google에 언어별 대체 페이지를 알리는 설정입니다. 한국어와 영어의 같은 제품 페이지를 연결한다면 각 버전에서 자기 자신과 상대 버전을 함께 지정하고, 양쪽 설정이 서로 대응하는지 확인해야 합니다. 메인 화면끼리만 연결하고 상세 페이지를 빠뜨리지 않았는지도 점검하세요. [Google 언어별 대체 페이지 설정](https://developers.google.com/search/docs/specialty/international/localized-versions)

예를 들어 `/ko/products/item-a`와 `/en/products/item-a`는 같은 제품의 언어 버전이라는 전제로 연결할 수 있습니다. 내용이 다른 제품을 단지 메뉴 위치가 같다는 이유로 대응시키면 안 됩니다. 위 주소는 설명용 예시입니다.

### canonical: 중복·유사 주소 중 대표 페이지를 지정합니다

영문 번역 페이지가 있는데 대표 주소를 모두 한국어 페이지로 지정하는 설정은 피해야 합니다. Google은 `hreflang`을 사용할 때 같은 언어의 canonical 페이지를 지정하도록 안내합니다. 별도 중복 주소가 없는 단순 구성이라면 한국어는 한국어 주소, 영어는 영어 주소를 대표로 지정하는 방식으로 검토할 수 있습니다. [Google canonical 권장사항](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls#best-practices)

이 설정들은 언어 관계와 대표 주소를 알리는 수단입니다. 설정을 추가하는 것만으로 해외 검색 노출이나 순위가 보장되는 것은 아닙니다. 검색엔진에 보내는 정보와 사용자가 실제로 읽는 내용을 함께 검수해야 합니다.

## 5. 번역 수정과 해외 문의를 누가 맡을지 정하세요

다국어 제작 비용은 언어 수만으로 결정하기 어렵습니다. **번역 분량, 제품·자료의 수, 언어별 기능 차이, 번역 검수와 수정 권한**이 작업 범위를 바꿉니다. 같은 페이지 수라도 이미지 안의 글자, PDF, 입력 오류 안내까지 수정해야 하는지에 따라 필요한 일이 달라집니다.

견적을 요청할 때는 아래 항목을 구분해 전달하세요.

- 오픈할 언어와 대상 고객, 첫 공개에 포함할 페이지 목록
- 번역문을 제공할 사람과 제품·기술 용어를 최종 확인할 담당자
- 이미지 속 문구, 첨부 자료, 알림 메일 등 본문 밖의 번역 범위
- 언어별 메뉴·문의·다운로드 기능이 같은지 다른지
- 한국어 원문을 고쳤을 때 번역본의 미수정 상태를 확인하는 방법
- 외부 번역 도구·CMS의 사용료와 계정 관리 주체

자동 번역을 초안에 활용하더라도 제품명·단위·공급 조건과 문의 안내는 담당자가 검토할 수 있어야 합니다. 게시 후 원문만 바뀌고 번역본이 오래된 상태로 남는 문제도 운영 범위에 넣으세요.

기업 정보를 어떤 순서로 전달할지 검토할 때는 [현대오토닉스 제작 사례](/work/hyundai-autonics)의 정보 구성을 참고할 수 있습니다. 이 링크는 기업 사이트의 디자인 참고용이며, 특정 다국어 기능이나 해외 검색 성과를 입증하는 사례로 제시하는 것은 아닙니다.

## 오픈 전에는 언어 선택부터 문의 접수까지 확인하세요

문장이 자연스러운지 확인하는 검수와 기능이 제대로 연결되는 검수를 나눠 진행하면 빠진 항목을 찾기 쉽습니다.

1. 각 언어 주소를 새 창에서 직접 열어도 올바른 콘텐츠가 표시되는지 확인합니다.
2. 제품 상세에서 언어를 바꿨을 때 같은 제품 페이지로 연결되는지 봅니다.
3. 번역되지 않은 메뉴·버튼·이미지 속 문구·다운로드 자료를 확인합니다.
4. 휴대전화에서 긴 영문 제목이나 메뉴가 잘리거나 입력을 가리지 않는지 봅니다.
5. 페이지별 언어 연결, 대표 주소, 공개된 URL의 색인 허용 상태를 확인합니다.
6. 담당자와 합의한 테스트 환경·절차에서 각 언어의 문의 결과와 담당자 수신 내용을 비교합니다.
7. 원문과 번역문을 수정할 계정·담당자·인수인계 범위를 확인합니다.

기존 주소도 바뀌는 작업이라면 [리뉴얼 SEO와 URL 이전 점검표](/columns/website-renewal-seo-checklist)를 함께 확인하세요. 다국어 확장과 주소 이전을 동시에 진행할수록 대응표가 중요해집니다.
