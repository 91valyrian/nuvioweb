## 카탈로그는 자료로 제공하고, 선택에 필요한 답은 페이지에 적으세요

**제품의 용도, 주요 사양, 적용 조건, 관련 자료와 견적 문의 경로는 웹페이지에서 바로 확인할 수 있도록 준비하는 편이 좋습니다.** 카탈로그 PDF는 상세한 기술 검토를 위한 자료로 연결하세요. 모든 내용을 웹에 옮길 필요는 없지만, 방문자가 파일을 열기 전에도 어떤 제품인지 판단할 수 있어야 합니다.

제조업 홈페이지를 기획할 때는 제품 사진의 크기보다 먼저 질문을 정해 보세요. ‘우리 설비에 사용할 수 있는가’, ‘비슷한 모델과 무엇이 다른가’, ‘도면은 어디서 받는가’, ‘견적을 받으려면 무엇을 알려야 하는가’에 답하는 구성입니다. 직접 결제하는 쇼핑몰과 달리 기술 검토와 상담을 거쳐 거래하는 기업에 맞춘 안내입니다.

이 글은 제품 상세페이지의 제작 범위를 정하기 위한 실무 제안입니다. 특정 기업의 구매 행동을 조사한 보고서나 문의 증가 성과를 제시하는 글은 아닙니다.

## 1. 제품 수를 세기 전에 분류와 모델의 관계를 정하세요

‘제품 100개를 등록한다’는 설명만으로는 제작 범위를 알기 어렵습니다. 같은 제품의 규격 차이인지, 용도와 설명이 다른 독립 제품인지에 따라 필요한 화면과 관리 기능이 달라집니다.

예를 들어 하나의 부품이 크기별로 여러 모델을 가진다면, 공통 설명과 모델별 사양표를 한 페이지에 구성할 수 있습니다. 반면 사용 환경과 선택 기준이 크게 다르면 제품별 설명 페이지가 필요할 수 있습니다. 아래는 분류를 논의하기 위한 가상의 예시입니다.

모델명만 아는 방문자와 용도만 아는 방문자를 함께 고려하세요. 전자는 모델 검색이나 명확한 제품명으로, 후자는 제품군 설명과 선택 기준으로 접근할 수 있어야 합니다. 필터는 실제로 관리할 수 있는 항목만 정하세요. 등록 자료에 없는 분류를 디자인에서 먼저 만들면 운영자가 매번 해석해서 입력해야 합니다.

제품별 페이지를 나눈다면 제품 목록에서 해당 주소로 이동하는 링크를 제공하세요. Google은 일반적으로 주소가 있는 HTML 링크를 통해 페이지를 발견할 수 있다고 설명합니다. 클릭 효과만 있는 카드보다 실제 링크가 있는지 개발 검수에 포함하는 것이 좋습니다. [Google 링크 권장사항](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)

## 2. 상세페이지는 ‘소개 → 조건 확인 → 자료 → 문의’ 순서로 점검하세요

첫 화면에는 제품명과 모델명, 용도, 대표 이미지, 핵심 특징을 배치합니다. 회사 소개 문구를 길게 반복하기보다 이 제품이 무엇을 하는지 먼저 설명하세요. 이어서 적용 조건과 사양, 자료, 문의로 이동하도록 구성할 수 있습니다.

### 제품 설명에는 적용 범위와 제한 조건을 함께 적으세요

‘고성능’, ‘다양한 환경에 사용’ 같은 표현만으로는 선택 기준이 생기지 않습니다. 공개할 수 있는 범위에서 사용 목적, 연결 대상, 설치 조건, 지원 범위를 구체적으로 정리하세요. 호환 여부가 상담 후 확정되는 제품이라면 그 사실도 안내해야 합니다.

인증이나 시험 자료는 실제 보유 자료를 바탕으로 적용 모델과 조건을 확인한 뒤 반영하세요. 자료가 없는 상태에서 장식용 인증 마크나 수치를 넣지 않습니다. 홈페이지 제작자가 기술 문구의 사실 여부를 추측하지 않도록 최종 검토 담당자를 정해 두세요.

### 사양표는 항목명·단위·조건을 통일하세요

비교할 모델마다 항목 이름이나 단위가 다르면 방문자가 다시 정리해야 합니다. 같은 의미의 항목은 명칭과 표시 순서를 맞추고, 값이 없는 항목은 ‘해당 없음’과 ‘별도 문의’를 구분하세요. 수치가 성립하는 시험 조건이나 옵션이 있다면 표 근처에 설명합니다.

사양표를 통째로 이미지로 넣으면 작은 화면에서 읽거나 내용을 복사하기 불편할 수 있습니다. 핵심 사양은 텍스트 표로 구현하고, 모바일에서는 표 내부를 가로로 넘기거나 모델별로 읽는 방식을 검토하세요. 표가 넓다는 이유로 글자 전체를 과도하게 줄이지 않는 것이 좋습니다.

개발 검수에서는 제목 셀과 데이터 셀이 구분되는지도 확인하세요. W3C는 표의 제목과 데이터 사이 관계를 HTML로 표현하도록 안내합니다. 이는 보조기술로 표를 읽을 때 맥락을 전달하는 데 필요합니다. [W3C 표 접근성 안내](https://www.w3.org/WAI/tutorials/tables/)

### 이미지는 제품 전체와 확인할 부분을 나누세요

대표 사진, 연결부나 조작부의 확대 사진, 크기·설치 방향을 설명하는 도면은 역할이 다릅니다. 같은 사진을 반복해서 채우기보다 각 이미지가 답할 질문을 정하세요. 도면의 글자와 치수는 휴대전화에서 확대해도 읽을 수 있는지 확인해야 합니다.

이미지 주변의 설명과 대체 텍스트도 실제 내용을 반영하세요. Google은 이미지가 놓인 페이지의 맥락과 대체 텍스트 등을 활용한다고 안내하며, 키워드를 무작정 나열하는 방식은 피하도록 권장합니다. [Google 이미지 SEO 안내](https://developers.google.com/search/docs/appearance/google-images)

## 3. 자료 다운로드와 견적 문의를 같은 제품에 연결하세요

카탈로그, 도면, 매뉴얼을 제공한다면 파일명만 나열하지 말고 자료명, 대상 모델, 언어와 개정일 등을 구분하세요. 파일 용량과 형식을 알리면 모바일에서도 다운로드 여부를 판단하기 쉽습니다. 구형 자료를 남겨야 한다면 현행 자료와 구분해 잘못된 버전으로 검토하지 않게 합니다.

공개 자료와 상담 후 제공할 자료도 미리 정하세요. 모든 다운로드에 회사명·연락처 입력을 요구할지, 일부 자료만 요청받을지는 자료의 공개 범위와 업무 처리 방식에 맞춰 결정해야 합니다. 단순한 자료실로 충분한지, 권한 관리나 요청 승인 기능이 필요한지에 따라 제작 범위도 달라집니다.

문의 버튼은 **어떤 제품에 관한 요청인지 이어지는지** 확인하세요. 제품에서 눌렀는데 빈 일반 문의폼만 나오면 모델명을 다시 입력해야 합니다. 선택한 제품명을 문의 화면에 보여주고 전송 내용에도 포함하면 담당자가 요청의 맥락을 확인하기 쉽습니다. 사용자가 잘못 선택했다면 수정할 수 있게 하세요.

견적에 필요한 정보는 제품과 업무에 따라 달라집니다. 수량, 사용 환경, 필요한 일정 등을 후보로 정하되, 방문자가 아직 모르는 정보를 모두 필수로 받지는 마세요. 접수 완료가 견적 확정이나 기술 적합성 승인으로 오해되지 않도록 후속 절차도 설명합니다. 입력 항목과 전송 확인은 [홈페이지 문의폼 제작 점검표](/columns/website-inquiry-form-checklist)에서 이어서 확인할 수 있습니다.

## 4. 견적을 요청할 때는 ‘화면 수’와 ‘등록·운영 범위’를 나눠 적으세요

공통 상세 화면 하나를 개발하는 일과 제품 데이터를 정리해 여러 개 등록하는 일은 다릅니다. 기존 카탈로그의 내용을 누가 옮기는지, 사진을 누가 준비하는지, 기술 문구를 누가 승인하는지까지 정해야 견적을 비교하기 쉽습니다.

- **콘텐츠 준비:** 기존 자료 취합, 제품별 원고 정리, 촬영·보정과 도면 정리의 담당자
- **화면과 기능:** 제품군 목록, 상세 템플릿, 모델 검색·필터, 자료 다운로드, 제품 연계 문의
- **초기 등록:** 등록할 제품·모델·파일의 수와 자료 제공 형식
- **관리자 기능:** 제품 복제, 순서 변경, 사양 항목 수정, 파일 교체, 공개 상태 변경
- **이전과 검수:** 기존 제품 주소 유지 여부, 자료 링크 점검, 기술 담당자의 최종 승인

관리자에서 ‘수정 가능’하다는 설명도 구체화하세요. 설명 문장만 수정되는지, 사양표 행을 추가할 수 있는지, 모델별 자료를 교체할 수 있는지는 서로 다른 기능입니다. 운영자가 실제로 수행할 작업을 목록으로 만들어 시연을 요청하는 편이 좋습니다.

제품 데이터가 많아 외부 시스템과 연결해야 한다면 별도 범위로 협의하세요. 기존 ERP나 재고 관리 시스템이 있다는 사실만으로 홈페이지와 바로 연동되는 것은 아닙니다. 제공 가능한 데이터, 연결 방법, 접근 권한과 운영 담당자를 확인한 뒤 검토해야 합니다.

[기업 홈페이지 제작 서비스](/service/corporate)에서 사업·제품 소개와 자료실의 기본 범위를 확인할 수 있습니다. 산업 분야의 시각 구성은 [현대오토닉스 제작 사례](/work/hyundai-autonics)를 참고하세요. 해당 사례 링크는 디자인과 콘텐츠 표현을 살펴보기 위한 자료이며, 이 글의 모든 기능 구현이나 검색·매출 성과를 입증하는 자료는 아닙니다.

## 5. 오픈 전에는 구매 담당자의 질문으로 검수하세요

디자인 승인과 기술 정보 승인을 나눠 진행하세요. 화면이 완성돼도 구형 모델의 파일이 연결되거나, 표의 단위가 빠지거나, 다른 제품명이 문의에 전달될 수 있습니다. 가능하면 기획에 참여하지 않은 사람이 대표 제품을 찾아보게 하고 막히는 지점을 기록해 보세요.

1. 용도만 알고 들어와도 적절한 제품군을 찾을 수 있나요?
2. 비슷한 모델의 차이와 적용 제한을 확인할 수 있나요?
3. 사양의 단위와 조건이 원본 자료와 일치하나요?
4. 휴대전화에서 사양표와 도면을 읽고 확대할 수 있나요?
5. 다운로드한 자료가 선택한 모델의 최신 자료인가요?
6. 문의 화면과 담당자에게 전달되는 내용에 제품 정보가 이어지나요?
7. 접수 실패 시 입력 내용과 재시도 방법을 확인할 수 있나요?
8. 운영자가 제품 설명과 파일을 교체한 뒤 실제 공개 화면에 반영되는지 확인했나요?

문의 전달 검수는 내부에서 합의한 테스트 환경과 수신처로 진행하세요. 공개된 운영 문의에 임의의 테스트를 반복하기보다 테스트 데이터와 정상 문의가 섞이지 않게 계획하는 것이 좋습니다.

## 제품 상세페이지 제작 전에 대표 제품 하나를 먼저 정리해 보세요

전체 제품을 한 번에 입력하기 전에 대표 제품 하나로 용도, 이미지, 사양, 자료, 문의에 필요한 정보를 모아 보세요. 그 자료를 기준으로 공통 템플릿과 제품별 예외를 구분하면 필요한 개발 범위와 준비할 자료가 선명해집니다.

이미 홈페이지가 있다면 모든 화면을 바꾸기 전에 제품 소개 영역부터 개선할 수 있는지 살펴보세요. 제품 주소까지 바뀐다면 [리뉴얼 URL 이전 점검표](/columns/website-renewal-seo-checklist)도 함께 검토해야 합니다.

제품 목록과 대표 카탈로그를 가지고 있지만 어디까지 웹으로 옮길지 정하기 어렵다면, [제품 상세페이지와 자료실 구성을 상담해 보세요](/contact). 현재 사이트 주소, 대표 제품 자료, 담당자가 직접 수정해야 할 항목을 함께 알려주시면 화면·등록·운영 범위를 나눠 논의할 수 있습니다.
