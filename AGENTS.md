# nuvioweb project rules

## Column writing and images

When asked to create, revise, or add a nuvio column (칼럼/컬럼/블로그 글), read `.agents/skills/nuvio-column-editor/SKILL.md` and its editorial reference. Apply it automatically to writing requests in this project. A completed new article includes MDX, its own thumbnail, related body images, descriptive alt/captions, verified claims, relevant internal links and a contextual consultation action. Do not stop at a chat draft when the user requests project content.

Preserve established article URLs and publication dates. Prefer improving an existing article when search intent overlaps. Never fabricate metrics, rankings, client work, testimonials or search volume. Use current primary sources for technical claims and distinguish examples from real project results.

## Portfolio writing from a website URL

For nuvio portfolio/제작 사례 creation or updates from a supplied website URL, read `.agents/skills/nuvio-portfolio-editor/SKILL.md` and its references. Inspect the actual desktop and mobile site for facts and visual direction, and write the existing `content/work/<slug>.mdx` schema. Generate a project-specific conceptual thumbnail and coordinated cover using the imagegen skill, unless the user supplies or selects those assets. Review existing list thumbnails for style/crop only; never reuse their pixels. Generated imagery is conceptual, not evidence of real client products, locations or UI.

Detail body images must be supplied by the user. Use only the provided files in the requested order and count; do not create screenshot boards, additional captures, montages or supporting AI artwork for the body. If body images are missing, finish independent copy/thumbnail/cover work and report the missing files rather than inventing or reusing a body image. For body-only revisions preserve thumbnail, cover and landing preview unless requested otherwise. Preserve supplied image content and aspect ratios; optimize file size with readable text and record before/after sizes, and preserve the modal's `portfolio.webp` integration without generating an additional board.

Keep portfolio hosting/canonical on `https://nuvio-web.com`; use the supplied client URL in `href`. Preserve established slugs when updating. Only state work scope, project year and results that are supplied or verifiable; identify missing capture/access evidence instead of fabricating a finished case. Preserve the modal's `portfolio.webp` integration.

## Styling conventions

- Across this project, use `rounded-[9999px]` for circular and pill shapes. Do not use the Tailwind `rounded-full` utility, including responsive or state variants. Keep deliberate finite corner radii on cards and panels.

## SEO invariants

- Use `src/lib/site.js` for canonical origin, metadata, JSON-LD escaping and valid dates. Keep `https://nuvio-web.com` as production origin. Preview deployments must stay noindex, including child googleBot overrides.
- Keep crawlable server-rendered anchors and unique URLs for column pagination. Filter pages are noindex/follow. Missing slugs return 404, genuine server failures must not be disguised as 404.
- Admin/backup pages must not be indexable. Keep real public content out of robots disallow rules. Never put unpublished draft content into the sitemap.
- Put JSON-LD in server-rendered script tags with safe serialization; use real publisher and current production URLs.
- Keep sitemap/RSS generated by App Router; dates must represent content edits, not build time. Do not add a second sitemap generator or rely on a build-time submission ping.
- Treat accepted lead delivery as DB storage OR successful email delivery. Never return success if both failed. Analytics events must not include submitted personal data.
- Validate changes with `npm run check:content`, appropriate regression tests, and `npm run build`; preview the actual UI for visual changes. Do not submit live test inquiries.

Deployment and Search Console/Search Advisor submissions require an explicit request or existing authorization. Report separately what is implemented locally and what is verified in production.
